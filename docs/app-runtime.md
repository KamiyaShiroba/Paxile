# App-owned runtime integration

The Tauri application owns one persistent `paxile-probe watch --managed --spy --block` child. `--block` remains mandatory startup mutation authorization; configuration alone cannot authorize mutation. Managed startup honors saved `enabled` independently of authorization. The application retains the child's stdin lifetime handle: EOF requests orderly shutdown, including lease stop and hook removal. Quit sends `off`, closes stdin, waits up to three seconds, and only then terminates its own child if necessary. No target application is terminated.

`set_enabled` sends `on` / `off` through the existing local control pipe. `save_config` validates and stages a separate config, sends `reload`, verifies increasing engine revision with unchanged startup authorization/requested switch, then sends the requested enable state. Only accepted engine requests are atomically persisted and published in app memory. Failed control (including a lost reply) or persistence triggers a compensating request for the previous config/switch; failed compensation explicitly reports `ROLLBACK FAILED` and unknown runtime state. Neither operation restarts the child or DLL. Errors propagate to the caller and core status. This is a compensated transaction, not cross-process crash atomicity; engine acceptance is not DLL/UI-thread application.

Rule changes use a bounded type-3 frame (revision, length, JSON config) over the existing live DLL connection. The DLL validates the full config, preserves startup authorization, replaces its policy, and changes control revision. The owner-thread hook/watchdog restores previously detached contexts and clears candidate evidence on revision changes. `config_received` is transport receipt, not a global acknowledgement that every window's owner thread has run. Hung UI threads remain unconfirmed. `applied_enabled` remains null. A connected DLL that does not acknowledge the transmitted config revision within two seconds, or disconnects before receipt, emits `runtime_unconfirmed` to logs/core error (possibly an unsupported older pinned DLL or unresponsive transport). An old pinned DLL cannot be hot-upgraded and engine reload success must never be presented as DLL application.

Managed discovery polls executables in active presets (selected profile or all for `auto`); it does not use `allow_exe` as an injection target. `allow_exe` is strictly a whitelist that permits IME and overrides blocking. Unknown applications/classes fail open. Only the CSP experimental preset is supplied in the catalog: this does not establish compatibility with other applications.

IPC added:
- `get_available_presets`: `[{name, display_name, executables, non_text_classes}]`
- `get_logs`: up to 500 chronological `{time, level, msg}` entries; `time` is Unix milliseconds encoded as string, messages capped at 4096 characters.
- `paxile-log`: emits the same real child-output/lifecycle entry shape.
- `get_core_status`: `{running, requested_enabled, applied_enabled, error}`. `requested_enabled` is queried from the live child, not saved config, and is null when unavailable; `applied_enabled` is always null. `get_status.enabled` follows the same live/null semantics (other fields describe committed configuration). Child exit is polled and reported, not automatically restarted into an already-pinned DLL. Frontends must handle the nullable switch rather than treating unknown as disabled.

The old PID/command UI IPC was removed. Frontend code is independently owned and must label custom executable entries as IME allow-list exemptions, not interception targets.

## Verification

Built matching workspace EXE/DLL under `target/runtime-control` before Windows tests. Workspace tests: 6 policy, 2 probe (real control pipe/external CLI and actual DLL hooks plus live config receipt), 1 spy owner-thread restoration. Tauri: 9 tests (including failed control compensation, persistence/rollback failure diagnostics, commit ordering, atomic file replacement, and reload revision/startup-gate validation), all-target tests and clippy with warnings denied passed. The probe transport test also verifies a synthetic non-acknowledging legacy peer emits an unsupported-DLL diagnostic. Workspace clippy with warnings denied passed. A separate no-target managed-child smoke run used empty presets: status initially off, on/off/reload succeeded with increasing revisions and null applied state; closing stdin exited with code 0 and real stdout output.

No UI was launched and no user application was injected into or terminated. Existing applications holding an older pinned DLL cannot be hot-upgraded by replacing its file; user-managed target restart is required to load this implementation. Live Chinese IME/CSP acceptance remains manual and must not be inferred from unit/build success.
